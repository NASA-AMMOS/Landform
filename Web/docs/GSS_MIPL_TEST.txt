TEST PLATFORM

This test requires a machine running Windows 10 with a 64 bit Intel or AMD CPU architecture.


VPN

If you are performing this test over VPN, you must use "full tunnel", not "split tunnel".


INSTALL NODE.JS

This test requires you to have installed node.js version 12.x.x.  These instructions were tested with version 12.16.1, but later versions in the 12.x.x series should also work.  If you have not already installed node.js 12.x.x, go to https://nodejs.org, download the latest 12.x.x release, and install it.

Verify you can run node.js by opening a windows command prompt and entering the command

node --version

It should return a string like "v12.16.1" corresponding to the version you installed.


DOWNLOADS

Create a temporary directory on a local disk with at least 2GB of free space.  All files related to the test will be located here, and the directory can be deleted after completing the test.  Download the following files into the directory:

https://github.jpl.nasa.gov/OnSight/Landform/releases/download/Version1.8.1/landform-gss-1_8_1.zip

https://github.jpl.nasa.gov/OnSight/Landform/releases/download/Version1.8.1/landform-test-data-shared.zip

https://github.jpl.nasa.gov/OnSight/Landform/releases/download/Version1.8.1/credss.exe

https://github.jpl.nasa.gov/OnSight/Landform/releases/download/Version1.8.1/unzip.ps1

For example, copy and paste each of those URLs in to Chrome to start the downloads.

Open a windows command prompt and change to the temp directory.  Run the following two commands to unzip the zip files:

powershell -ExecutionPolicy Unrestricted ./unzip.ps1 landform-gss-1_8_1.zip .

powershell -ExecutionPolicy Unrestricted ./unzip.ps1 landform-test-data-shared.zip .

Be sure to include the final "." in each of those commands.  You will be prompted with a "Security warning", select "[R] Run once".  You should then have two subdirectories and two files in your temp directory, e.g.

tmpdir/landform-gss-1_8_1/
tmpdir/landform-test-data-shared/
tmpdir/credss.exe
tmpdir/unzip.ps1


AWS CREDENTIALS

This test will use some AWS resources including DynamoDB and S3.  It will require access to the AWS account "mipl-dev/power_user".  One way to check if you have access is (after connecting "full tunnel" VPN, if working remotely) is to go to the URL "http://goto/govcloudconsole" in Chrome, and make sure you see "Account: mipl-dev (105249944904) with a checkbox for "power_user" under it.  If you do not, or if you get an error when logging in with that account, contact Adrian Tinio or Jeff Liu to get access.

Open a Windows command prompt, change to the temp directory you created above, and copy and paste the following lines:

set LANDFORM_AWS_REGION=us-gov-west-1
set LANDFORM_AWS_ACCOUNT=105249944904
set LANDFORM_AWS_ROLE=power_user
set LANDFORM_AWS_ENV=gov
set LANDFORM_AWS_PROFILE=credss-mipl-dev
set LANDFORM_AWS_DURATION=14400

credss.exe --region %LANDFORM_AWS_REGION% --account %LANDFORM_AWS_ACCOUNT% --role %LANDFORM_AWS_ROLE% --env %LANDFORM_AWS_ENV% --section %LANDFORM_AWS_PROFILE% --aws-only --duration %LANDFORM_AWS_DURATION%

You will be prompted for your JPL username and password.  This will acquire a temporary AWS authentication token with a 4 hour duration.  If you need more time to complete the test, run the credss.exe command again.

Note: you don't need to manually substitute text for variables like %LANDFORM_AWS_REGION%.  Just copy and paste the "set" commands followed by the credss.exe command line.  The set commands will set values as environment variables.  Windows will automatically replace e.g. %LANDFORM_AWS_REGION% with us-gov-west-1 in the command line.

GSS TEST PROJECT

Open a new Windows command prompt, change to the temp directory you created above, and copy and paste the following lines:

set API_TOKEN=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1aWQiOiJ2b25hIiwiaWF0IjoxNTkzMjAxMzcyLCJleHAiOjE4MTM5NTMzNzJ9.ZDw3NYlqWaU1KKNBdZxNZa00eCBufBKXb0ZxBX9zhKY

set PROJECT_NAME=test0
set MESH_FILE=landform-test-data-shared/stick/stick.ply
set TEXTURE_FILE=landform-test-data-shared/stick/stick.jpg

Then use that command prompt to follow the next 10 steps.

1. Create project:

curl -sS --request POST --url "%SERVER_URL%/api/projects/%PROJECT_NAME%" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response contains `"success":true`.  Example response:

{"id":1,"running":false,"success":true,"exitCode":0,"error":null,"started":1593190323668,"ended":1593190326124}
   
2. List projects:

curl -sS --request GET --url "%SERVER_URL%/api/projects" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response contains PROJECT_NAME.  Example response:

[
    "test0"
]

3. Upload input files:

curl -sS --request POST --url "%SERVER_URL%/api/projects/%PROJECT_NAME%/upload" --header "x-landform-token: %API_TOKEN%" --form "mesh=@%MESH_FILE%" --form "texture=@%TEXTURE_FILE%"

Validation: check that the response contains `"success":true`.  Example response:
   
{"id":3,"running":false,"success":true,"exitCode":0,"error":null,"started":1593190654817,"ended":1593190658155}

4. Run project:

curl -sS --request POST --url "%SERVER_URL%/api/projects/%PROJECT_NAME%/run" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response contains `"success":true`.  Example response:

{"id":4,"running":false,"success":true,"exitCode":0,"error":null,"started":1593190740442,"ended":1593190742395}

5. Get project metadata:

curl -sS --request GET --url "%SERVER_URL%/api/projects/%PROJECT_NAME%" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response contains `"StartedRunning": true`.  Example response:

    "InternalMeshFormat": "ply",
    "InternalImageFormat": "png",
    "TilesetDir": "www",
    "TilesetMeshFormat": "b3dm",
    "TilesetImageFormat": "jpg"
  },
  "Inputs": [
    {
      "Name": "stick",
      "MeshUrl": "https://mipl-dev-landform.s3.amazonaws.com/landform-web/landform-dev-vona-quarth/input/test0/stick.ply",

6. Poll project metadata about every 30 seconds until the response contains `"FinishedRunning": true`.  This should take about 5 minutes for the "stick" dataset.

7. Get project result URL:

curl -sS --request GET --url "%SERVER_URL%/api/projects/%PROJECT_NAME%/result?redirect=false" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response is a URL ending in "tileset.json".  Example response:

"https://mipl-dev-landform.s3-us-gov-west-1.amazonaws.com/landform-web/landform-dev-vona-quarth/www/test0/tileset.json"

8. Get project viewer URL:

curl -sS --request GET --url "%SERVER_URL%/api/projects/%PROJECT_NAME%/view?redirect=false" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response is a URL ending in "tileset.json".  Example response:

"http://localhost:8081/viewer/index.html?Tileset=https%3A%2F%2Fmipl-dev-landform.s3-us-gov-west-1.amazonaws.com%2Flandform-web%2Flandform-dev-vona-quarth%2Fwww%2Ftest0%2Ftileset.json"

9. Copy and paste the project viewer URL from the last step in a Chrome browser window to visually inspect the result.  Note: don't copy the double quotes which surround the URL.  The "stick" test dataset may initially appear very small in the center of the viewer.  Hit the "f" key on the keyboard to fit the view to the dataset, which will zoom it in.

10. Delete project:

curl -sS --request DELETE --url "%SERVER_URL%/api/projects/%PROJECT_NAME%" --header "x-landform-token: %API_TOKEN%"

Validation: check that the response contains `"success":true`.  Example response:
   
{"id":7,"running":false,"success":true,"exitCode":0,"error":null,"started":1593191585989,"ended":1593191599176}

CLEANUP

Hit CTRL-C in the command prompt windows running the GSS master and worker to kill them.  Then close all command prompts.

Delete the local temp directory containing all the files used for the test.

Go to http://goto/govcloudconsole, select account mipl-dev/power_user, click Sign In.  Under Database click DynamoDB, then dlick Tables under DynamoDB in the left hand pane.  In "filter by table name" enter the Venue name you noted above.  Generally it will be in the form landform-dev-USER-MACHINE (e.g. landform-dev-vona-quarth).  Four tables should be found, e.g.

landform-dev-USER-MACHINE-TilingInput
landform-dev-USER-MACHINE-TilingInputChunk
landform-dev-USER-MACHINE-TilingNode
landform-dev-USER-MACHINE-TilingProjects

For each table, click the circle next to the table name to select it, then click Delete Table.  Follow the instructions to delete the table and any associated CloudWatch alarms.  Do not make a backup.
